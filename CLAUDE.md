# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`nattes` is a single-crate Rust library: a typesafe, in-process message queue inspired by NATS. Subjects are declared as a tree of types with the `events!` macro, so wrong paths, parameters, or message types fail at compile time. `README.md` is the user-facing spec. Keep it in sync when public behavior changes.

## Commands

The dev shell comes from devenv (`devenv.nix`, Rust enabled) and loads through direnv (`.envrc`).

```sh
cargo build
cargo test                       # unit tests (src/tests.rs) + doctests in lib.rs
cargo test <name>                # single test by name substring
cargo test --doc                 # doctests only (includes compile_fail checks)
cargo clippy --all-features      # lint, as run in CI
cargo bench --bench throughput   # criterion multi-threaded throughput (noisy, wall-clock)
cargo bench --bench throughput -- fan_out   # one bench group
cargo bench --bench instructions # exact instruction counts under Valgrind (gungraun), diffed against the last run
```

Use `instructions` to iterate on performance: counts are reproducible, so a small change shows up. It needs `gungraun-runner` at the same version as the `gungraun` dev-dependency (`cargo install gungraun-runner --version 0.20.0`). Valgrind comes from the dev shell. To compare against a fixed point, run `cargo bench --bench instructions -- --save-baseline=<name>` before a change and `-- --baseline=<name>` after it. Exception: `subscribe`/`unsubscribe` with 1000+ existing subscriptions move by up to ~8% between identical builds (likely the random hash seed of the parameter map), so treat changes there as noise unless they persist.

Both benches share the event tree, `Payload`, and `start()` from `benches/common/mod.rs` (a plain module, not a bench target). Put shared setup there rather than copying it.

CI (`.github/workflows/`) runs `cargo check`, `cargo build`, `cargo test`, and clippy (SARIF upload, non-blocking).

The repo is also a jujutsu repo (`.jj/`), so git may show a detached `HEAD`.

## Architecture

`src/lib.rs` holds the crate docs (including the `compile_fail` doctests) and re-exports the public API from private modules. Request/reply (and `BusError`) lives in `src/request.rs`, and tests are in `src/tests.rs`. Modules:

- **`tree.rs`, event tree (`Node`, `Step`, `subject`)**: each `Topic` enum generated by `events!` implements `Node`, which walks one level down. `subject()` follows that chain to build `git.push` / `user.<id>.delete` strings.
- **`nav.rs`, navigation (`Prism`, `Param`, `Wild`/`Is`, `AppendParams`)**: a `Prism<A>` trait is one step down the tree, to `Prism::B` with wildcard params `Prism::Q`. `project` borrows a `B` (plus `Q`) out of an `A`, and `inject` builds an `A` from a `B` (`None` on a wildcard step). The implementations are plain values, `Plain` and `ParamStep` (fn pointers plus the `Wild`/`Is` selector), not closures, so navigating doesn't allocate. `key()` builds the step's `Key` (segment name plus `None`/`Any`/`Is(ParamKey)`) only when subscribing. `ParamKey` wraps an `Arc<dyn ParamValue>` (`tree.rs`), which is any `Clone + Eq + Hash + Display` type compared and hashed through `dyn` methods. It implements `Borrow<dyn ParamValue>`, so publishing looks up the event's own `&dyn ParamValue`. `Display` only serves `subject()`. `AppendParams` concatenates wildcard param tuples, implemented up to 6 params via `impl_append!`.
- **`bus.rs`, untyped bus core (`Core`, `Interest`, `Queue`, `Entry`, `Group`)**: works only with `Event = Arc<dyn Node>` and `&dyn Any` matchers. Subscriptions live in `Interest`, a NATS-sublist-style trie keyed by the channel's `Key` path. A subscription sits on its channel's node and wants everything at or below it. Each node lists `(segment name, Edges)` pairs (a `Vec`: siblings are few, so a scan beats hashing). `Edges` holds the plain, `Any`, and fixed-value children, the latter in an `imbl::HashMap<ParamKey, _>`: a persistent HAMT, so copy-on-write copies one path instead of every sibling and (un)subscribing stays O(log n) with many parameter values (measured 449k → 12k instructions at 10k subscriptions, for ~5% on parameterized publish). The trie sits in an `ArcSwap<Interest>`, so publishing reads it without a lock. (Un)subscribe updates it copy-on-write (`Arc::make_mut`) under the `state` mutex, and empty nodes are pruned. `publish` walks the event's `Node::step` chain without allocating: `Step::param` is a `&dyn ParamValue`, looked up by value and never formatted. It follows both `Any` and `Is(value)` edges on parameters and runs matchers as it goes, catching panics (a panic counts as no match). The trie matches names and parameter values exactly, so only subscriptions with filters get a matcher. Queue group members are stored on their node as `Members`, in subscription (id) order. Group names are global per bus, so one group can span several nodes on a subject. `State.groups` counts members and forgets a group with its last one. Only in that case does `route` merge and sort the members per publish. `deliver` pushes to every non-full queue first and only then awaits `Overflow::Wait` queues, in a separate `wait` future that the common no-wait path never builds. Queue groups pick one member per group (`pick`): the first idle (`parked`, waiting in `next()`) accepting member from the round robin position, else the first accepting one. `Queue` is a `Mutex<VecDeque>`: a lock-free queue was measured and lost on fan-out, where each queue has one publisher and the lock is uncontended. The `concurrent_*` stress tests cover the handoffs across threads. A push only wakes the subscriber if it is `parked`. `Overflow::Wait` publishers set `wanted` and are woken together once the queue drains to half. `lock()` ignores poisoning on purpose.
- **`channel.rs`, `Channel<T, P>`**: a typed view rooted at `T`. It holds the shared `Arc<Core>` and an `Arc<dyn Route<T, P>>`, a chain of `Hop { parent, step }` ending at `Root<R>`. A route projects a root event to `(P, &T)`, injects a `T` into a root event, and lists the `Key` path (built only on subscribe). `at_prism` adds one `Hop`, which is one allocation per step. That keeps `topic!(bus, user.id(x).delete).publish(..)` cheap; the `routing` bench builds a channel per message. `publish` exists only on `Channel<T, ()>`, so wildcard channels can't publish. This is checked at compile time and relied on by `compile_fail` doctests.
- **`subscription.rs`, subscriptions**: `SubscriptionBuilder` implements `IntoFuture` (ready immediately). `Subscription` is a `Stream`, and dropping it unsubscribes and closes the queue, which clears pending requests so requesters get `NoReply`. `Msg<T, P>` keeps the root event and re-projects on `Deref`/`params()`.
- **`macros.rs`**: `channel!` makes `Channel::<mod::Topic>::new()`. `topic!` turns `a.b(x).c()` into calls on generated `Steps` types (`()`/`_` becomes `Wild`, a value becomes `Is(v)`). `events!` is a tt-muncher (`@munch` with accumulators for variants, child modules, `Node` arms, and `Steps` methods; `@chain` desugars `a => b`). Each level becomes a module with `use super::*`, which is why `events!` must be used at module level.

`request.rs` adds `Request<RQ, RP>` as a leaf message type wrapping a tokio oneshot, plus `Channel<Request<..>>::request` / `request_timeout`. The only tokio runtime dependency is the timer in `request_timeout`; everything else must stay executor-agnostic (tokio is used only for `sync`).

## Conventions

- Compile-time guarantees are part of the API. When changing navigation or publishing, update the `compile_fail` doctests in `lib.rs` and the "Compile-time checks" section of the README.
- Every handle and future must stay `Send + Sync`, and messages are `Send + Sync + 'static`.
- Generated code silences naming lints (`non_camel_case_types`, `clippy::new_ret_no_self`, …) because topic names are lowercase subject segments.
